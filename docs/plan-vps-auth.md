# План: переезд на VPS hoster.kz и новая схема входа

Согласовано 2026-09-05. Следующая сессия начинает отсюда.

## 1. Железо и что на нём живёт

Тариф hoster.kz **Cloud 1-1-25**: 25 ГБ NVMe, 1 ГБ RAM, 1 vCPU, 1 IP, 37 200 ₸/год, тест 7 дней.

- Хватает: Next.js в режиме standalone ест 200–300 МБ, nginx 10 МБ, SQLite почти ничего. Итого ~400 МБ под нагрузкой.
- Не хватает на сборку: `next build` требует 1,5–2 ГБ. Сборка идёт не на сервере, а в GitHub Actions при пуше в `main`; на сервер по SSH заливается уже собранный `.next/standalone`. На всякий случай на сервере включается 2 ГБ swap.
- Диск: 25 ГБ минус система ≈ 20 ГБ = ~260 фильмов по 76 МБ (PNG + MP3 128). Плюс правило очистки: исходники (картинки, звук) удаляются через 30 дней или сразу после экспорта MP4, текст сцен и стоимость остаются навсегда.
- Хранилище: файлы на диске сервера `/var/lib/studio/films/<id>/scene_N.png|mp3`, `refs/<user>/...`; nginx отдаёт их по `/media/...` с кэшем.
- База: **SQLite** (один файл `/var/lib/studio/studio.db`, драйвер better-sqlite3). Postgres и Supabase не нужны. Таблицы: `users`, `admins`, `invite_codes`, `login_codes`, `video_generations`, `pipeline_errors`.
- Бэкап: ночью `sqlite3 .backup` + tar фильмов в Cloudflare R2 (10 ГБ бесплатно) или снапшот hoster.kz. Хранить 7 копий.
- Процессы: Node 20 под systemd (или pm2), nginx как reverse proxy на :3000, автоперезапуск.
- Vercel и Supabase отключаются после переезда; лимит функции 300 с исчезает, сценарий можно делать одним этапом.

## 2. Cloudflare перед сервером

- DNS через Cloudflare, оранжевое облако (proxy). Реальный IP сервера скрыт; firewall сервера пускает 80/443 только с IP Cloudflare, SSH только по ключу.
- TLS: Cloudflare Origin Certificate на nginx, режим Full (strict).
- WAF, защита от ботов, rate limiting на `/api/auth/*` и `/admin/*` (например, 10 запросов в минуту с IP).
- Дополнительно (по желанию): Cloudflare Access на `/admin` с One-time PIN на почту. Это второй замок поверх нашего входа, бесплатно до 50 человек.

## 3. Кто и как входит

### Администраторы
- Список стартовых админов в `.env`: `ADMIN_EMAILS=reli.sheets1@gmail.com,второй@...`. Никто вне списка и таблицы `admins` в админку не попадёт.
- Вход на `/admin`: вводит почту → на почту уходит 6-значный код → вводит код → сессия админа (HttpOnly cookie, подпись HMAC, 12 часов, «выйти везде» через epoch).
- Код живёт 10 минут, 5 попыток, потом новый; не чаще одного кода в минуту на почту и 10 в час с IP.
- Внутри админки: поле «добавить админа» (почта) → запись в `admins`; удалить можно любого, кроме себя и почт из `.env`.

### Обычные пользователи
1. **Заявка.** На сайте форма: почта → кнопка «Отправить заявку». Создаётся запись `users` со статусом `pending`. Пользователю на почту: «заявка принята, ждите».
2. **Подтверждение админом.** В админке таблица заявок: почта, дата, статус. Кнопка «Одобрить» создаёт **код приглашения, привязанный к этой почте** (например `KZ-7F3A-9Q2M`, живёт 7 дней, одноразовый). Админ отправляет код человеку сам (личка, мессенджер). Можно и автоматически письмом, галочка в админке.
3. **Регистрация.** Пользователь вводит почту + код приглашения. Код проверяется только для этой почты. Дальше ему на почту 6-значный код входа (та же схема, что у админов) → сессия пользователя (30 дней).
4. **Вход в следующий раз.** Почта → 6-значный код на почту → сессия. Пароля нет, воровать нечего.
5. **Личный кабинет.** Первым делом вставляет свой ключ ElevenLabs (хранится зашифрованным AES-256-GCM, как сейчас). Без ключа генерация недоступна. Видит остаток кредитов ElevenLabs, остаток генераций, архив своих фильмов со стоимостью.
6. **Лимиты.** В админской таблице у каждого пользователя: статус (pending / approved / blocked), лимит генераций, использовано, кнопки «+5», «заблокировать», «сбросить ключ». Заблокированный теряет сессию мгновенно.

### Общий пароль сайта (по желанию)
- `SITE_PASSWORD=1599`: экран-заглушка до любой формы. Полезно на время теста, отключается одной переменной.

## 4. Письма

- Отправка через Resend (3 000 писем в месяц бесплатно) или SMTP hoster.kz на своём домене. Переменные: `MAIL_FROM`, `RESEND_API_KEY` (или `SMTP_*`).
- Три шаблона: код входа, заявка принята, код приглашения (если админ включил автоотправку).

## 5. Что переписывается в коде

- `src/lib/db.ts`: SQLite вместо Supabase (те же функции, другой драйвер).
- `src/lib/storage.ts`: запись/чтение файлов на диск вместо Supabase Storage; публичные URL `/media/...`.
- Маршруты `api/auth/*`: заявка, код приглашения, отправка и проверка 6-значного кода, сессии.
- Маршруты `api/admin/*`: заявки, коды приглашения, лимиты, админы.
- Страницы: `/` (заявка, вход по коду, кабинет), `/admin`.
- Скрипт миграции данных из Supabase не нужен: видео уже удалены, пользователей заведём заново.
- Очистка: cron раз в сутки удаляет медиа старше 30 дней.
